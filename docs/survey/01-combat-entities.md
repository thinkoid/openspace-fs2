# Cluster 01 — Combat entities

Subsystems: **ship**, **weapon**, **cmeasure**. The entities that fight, and the
projectiles and decoys between them. See [README](README.md) for conventions
(symbol-first anchors; `[retail]` = immutable branch).

> **Structural note:** `code/ship/` holds *two* subsystems. This file covers the
> ship **entity** (~14k) and, below, the flight/order **AI** (~18k: `ai.cpp` 102L,
> `aicode.cpp` 14,786L, `aibig.cpp` 1,574L, `aigoals.cpp` 1,875L; there is **no**
> `aiturret.cpp` — turret AI lives inside `aicode.cpp`). They share the directory
> but are distinct subsystems.

---

### ship  (~14k master, excluding the ~17k AI files aicode/aibig/aigoals which are a separate subsystem)
- **Purpose:** The player/AI combatant entity: instantiation from `ships.tbl`, per-frame lifecycle, weapon firing, subsystem/hull/shield damage, death sequence, and warp effects.
- **Entry points:** `ship/ship.cpp: ship_create()`, `ship_set()`, `ship_process_pre()` / `ship_process_post()` (per-frame), `ship_delete()`, `ship_render()`, `ship_fire_primary()` / `ship_fire_secondary()`, `parse_shiptbl()` / `parse_ship()`; damage in `ship/shiphit.cpp: ship_apply_local_damage()` / `ship_apply_global_damage()` / `do_subobj_hit_stuff()` / `ship_hit_kill()`; death & warp in `ship/shipfx.cpp: shipfx_blow_up_model()` / `shipfx_warpin_start()` / `shipfx_warpout_start()` / `shipfx_large_blowup_init()`.
- **Core state:** `ship/ship.cpp: Ships[MAX_SHIPS]` (live instances) indexed by `object.instance`; `Ship_info[MAX_SHIP_TYPES]` (parsed table archetypes, `Num_ship_types`); per-instance `ship_weapon weapons` (bank ammo/state); subsystem pool `Ship_subsystems[MAX_SHIP_SUBOBJECTS]` handed out via the `ship_subsys_free_list` intrusive linked list; ship-object index list `Ship_objs[]` / `Ship_obj_list`; shield damage records `shield.cpp: Shield_hits[MAX_SHIELD_HITS]`.
- **Mechanism:** `parse_shiptbl()` fills `Ship_info[]` once at boot; `ship_create()` grabs an `object`, an `Ships[]` slot, allocates per-instance `ship_subsys` nodes off the free list, and calls `physics_ship_init()`. Every frame `ship_process_post()` runs ETS energy, afterburners, subsystem-disruption checks, and `ship_dying_frame()`. Damage flows shield→hull through `apply_damage_to_shield()` and `do_subobj_hit_stuff()`, and death triggers the `shipfx` blow-up/debris pipeline.
- **Rare knowledge:** The subsystem free-list allocator (`GET_FIRST(&ship_subsys_free_list)` with a dummy sentinel node) is a classic 1998 fixed-pool-with-intrusive-list idiom worth mining. `shipfx.cpp: shipfx_large_blowup_*` implements the multi-stage capital-ship death animation; the shield is a per-triangle hit-decal system (`gshield_tri` / `Global_tris`) that mirrors the model's shield mesh — non-obvious and undocumented elsewhere. ETS (Engine/Shield/Weapon energy transfer) coupling lives right in the post-frame path.
- **Deps:** object/physics, model (`polymodel`, submodels, shield mesh), ai (`Ai_info`, `ai_index`), weapon (firing creates `Weapons[]`), fireball/particle/debris (death fx), hud/ets, network (`nprintf` sync notes).
- **Extraction seams:** Deeply entangled — `Ships[]`/`Ship_info[]` are referenced across nearly every subsystem via `object.instance`. Shield (`shield.cpp`) and afterburner (`afterburner.cpp`) are the cleanest sub-cuts; the death/warp fx in `shipfx.cpp` are separable behind `object`+`polymodel`. The AI files (aicode/aibig/aigoals) are already a distinct cut despite living in `ship/`.
- **Port notes:** Light. Demo-build gating remains: `shield.cpp` compiles a full renderer under `#ifndef DEMO` and a set of no-op stubs (`add_shield_point(){}`, `apply_damage_to_shield(){return damage;}`) under `#else`. Dead `#if 0` block in `ship_render()` (big-ship attack-point debug draw). Retail-era authorial comments preserved (`// AL 1-6-98`, `// MK, 3/12/98`, `Int3()` / "get allender" asserts). No fs2open-hash bugfix references seen in this subsystem.

### weapon  (~3.3k weapons.cpp; ~10k with beam/swarm/corkscrew/emp/flak/trails/muzzleflash/shockwave aux files)
- **Purpose:** Projectile/missile entities: table-driven weapon archetypes, spawn, per-frame flight + homing, and impact/detonation handling.
- **Entry points:** `weapon/weapons.cpp: weapon_create()`, `weapon_process_pre()` / `weapon_process_post()` (per-frame), `weapon_home()` (guidance), `weapon_hit()` (impact), `weapon_set_tracking_info()`, `weapon_delete()`, `weapon_render()`, `parse_weaponstbl()` / `parse_weapon_expl_tbl()`.
- **Core state:** `weapons.cpp: Weapons[MAX_WEAPONS]` (live projectiles, `Num_weapons`) indexed by `object.instance`; `Weapon_info[MAX_WEAPON_TYPES]` (parsed archetypes, `Num_weapon_types`) with `wi_flags` (`WIF_HOMING_HEAT`/`WIF_HOMING_ASPECT`/`WIF_BOMB`/`WIF_BEAM`…) and `subtype` (`WP_LASER`/`WP_MISSILE`); per-instance homing fields `homing_object`, `homing_subsys`, `target_sig`, `creation_time`, `lifeleft`.
- **Mechanism:** `parse_weaponstbl()` loads `weapons.tbl` into `Weapon_info[]`; ship firing calls `weapon_create()`, which linearly scans `Weapons[]` for a free slot (`weapon_info_index < 0`) and, when near `MAX_WEAPONS`, calls `collide_remove_weapons()` to reclaim. `weapon_process_post()` runs `weapon_home()` for guided types — a 0.25s arming delay, heat/aspect retarget logic keyed on target `signature` vs `target_sig`, and speed-clamp steering via `phys_info.desired_vel`. `weapon_hit()` dispatches damage, shockwaves, EMP, and spawn (child) weapons.
- **Rare knowledge:** Signature-based target validation (`homing_object->signature != wp->target_sig`) is how the engine cheaply detects that a homing target was destroyed and its object slot recycled — worth mining. Beam weapons are explicitly excluded from `weapon_create()` (`Assert(!(wi_flags & WIF_BEAM))`) and handled entirely in `beam.cpp`, a separate ~3k continuous-damage subsystem. Countermeasure spoofing is driven from here via `Cmeasures_homing_check`. Commented-out "bombs drop for a bit" and aspect-lock code preserves the original design reasoning verbatim.
- **Deps:** object/physics, model, ship (parent `objnum`, `ship_subsys` targets), cmeasure (homing decoys), fireball/particle (`trails.cpp`, `muzzleflash.cpp`), shockwave/emp/flak on impact, collision.
- **Extraction seams:** Fairly self-contained around `Weapons[]`/`Weapon_info[]` + `object`/`phys_info`. The effect aux files (`trails`, `swarm`, `corkscrew`, `emp`, `flak`, `shockwave`, `muzzleflash`) are individually liftable behind small headers; `beam.cpp` is already a near-independent cut. Cleanest boundary: homing depends on ship `signature`/subsystem, so lift with a target-abstraction shim.
- **Port notes:** Minimal — no `#if 0`/fs2open markers in `weapons.cpp`. Retail authorial comments intact (`// AL 4-8-98`, `// MK, 3/12/98`); commented-out original blocks (bomb-drop, delete-for-AI-ships) left in place rather than removed.

### cmeasure  (~294 master)
- **Purpose:** Countermeasure decoys ("chaff/flares") ejected by ships to spoof homing missiles.
- **Entry points:** `cmeasure/cmeasure.cpp: cmeasure_create()`, `cmeasure_process_pre()` / `cmeasure_process_post()` (per-frame), `cmeasure_delete()`, `cmeasure_render()`, `cmeasure_select_next()`, `cmeasure_init()`.
- **Core state:** `cmeasure.cpp: Cmeasures[MAX_CMEASURES]` (live decoys, `Num_cmeasures`) with `subtype` (== `CMEASURE_UNUSED` marks a free slot), `lifeleft`, `team`; archetypes `Cmeasure_info[MAX_CMEASURE_TYPES]`; the global handshake flag `Cmeasures_homing_check` read by `weapon_home()`.
- **Mechanism:** `cmeasure_create()` linear-scans `Cmeasures[]` for a `CMEASURE_UNUSED` slot, spawns an `OBJ_CMEASURE` object with physics/render, randomizes `lifeleft` and a launch displacement, and sets `Cmeasures_homing_check = 2` so the missile-homing code rescans all objects for two frames (the comment notes one frame causes sync problems from end-of-frame object creation). Decoys are dumb ballistic objects; the spoofing decision lives in `weapon_home()`, which weights `CMF_DUD_HEAT`/`CMF_DUD_ASPECT` flags against the seeker type.
- **Rare knowledge:** The two-frame `Cmeasures_homing_check` handshake is a subtle era workaround for objects created at end-of-frame not yet being visible to homing scans — hard to find explained today. The countermeasure itself carries no homing logic; it's a passive attractor evaluated by the weapon seeker, an inversion many would not expect.
- **Deps:** object/physics, ship (source `objnum`, `team`), weapon (homing evaluation), model/render. Debug gate on `Countermeasures_enabled`/`Ai_firing_enabled`.
- **Extraction seams:** Highly self-contained (single ~300-line file + header). The only outward coupling is the `Cmeasures_homing_check` global consumed by `weapon_home()` and the `OBJ_CMEASURE` object type — lift cleanly by exposing that flag through a weapon-side accessor.
- **Port notes:** — (no `#if 0`/fs2open markers; only `#ifndef NDEBUG` debug-enable guard and retail `// MK, 3/12/98`-style comments).

### AI (aicode/aibig/aigoals, ~18k in code/ship/)

- **Purpose:** The flight/order/goal "brain" for every non-player ship — per-frame steering, combat, docking, waypoint/path following, plus a priority-sorted goal stack fed by mission SEXPs and player orders, and independent per-subsystem turret AI. (Note: there is **no `aiturret.cpp`** in this tree — turret AI lives inside `aicode.cpp`; the file inventory is `ai.cpp` 102L, `aicode.cpp` 14,786L, `aibig.cpp` 1,574L, `aigoals.cpp` 1,875L, headers `ai.h`/`aibig.h`/`aigoals.h`/`ailocal.h`.)
- **Entry points:**
  - `ship/aicode.cpp: ai_process(obj, ai_index, frametime)` (~13464) — per-ship, per-frame entry called from the ship loop. Zeroes `AI_ci` control-info, calls `ai_frame()`, then feeds the resulting controls to `physics_read_flying_controls()` (unless docking/warp submodes set `rfc=0` to move under thruster control).
  - `ship/aicode.cpp: ai_frame(objnum)` (~13195) — the spine. Order: self-destruct check → `ai_process_mission_orders()` (goal → mode) → shockwave avoidance → repair/rearm frame → play-dead/collision-recover early-outs → target selection (`set_target_objnum`, `find_enemy`) → stealth bookkeeping → shield/cmeasure/evade management → `ai_execute_behavior(aip)` → `process_subobjects(objnum)` (turrets) → `maybe_resume_previous_mode`.
  - `ship/aicode.cpp: ai_execute_behavior(aip)` (~12293) — the mode dispatch `switch (aip->mode)` that fans out to the per-mode handlers.
  - `ship/ai.cpp` — bookkeeping only: `ai_get_slot`/`ai_free_slot`, `ai_get_goal_ship_name`, and the definitions of `Ai_info[]`/`Player_ai`/`Goal_ship_names[]`.
  - `ship/aigoals.cpp: ai_process_mission_orders(objnum, aip)` (~1477) — the goal→behavior translator (see (b)).
  - Per-mode handlers (all `ship/aicode.cpp` unless noted): `ai_chase()` (~7476), `ai_evade()`, `ai_still()` (~9407), `ai_stay_near()`, `ai_guard()` (~8963), `ai_waypoints()` (~4211), `ai_dock()` (~9504), `ai_big_ship()` (aibig ~1055), `ai_path()` (~3909), `ai_safety()` (~4179), `evade_weapon()`, `ai_big_strafe()` (aibig ~1414), `ai_bay_emerge()`/`ai_bay_depart()` (~12048), `ai_sentrygun()`, `ai_warp_out()`.
- **Core state:**
  - `ai_info Ai_info[MAX_AI_INFO]` defined in `ship/ai.cpp`; `MAX_AI_INFO == MAX_SHIPS`. Slot linked to a ship via `Ships[].ai_index`; `Player_ai` points at the player's slot. `struct ai_info` (`ai.h` ~270–440) is huge: `mode`/`previous_mode`/`submode`/`previous_submode` + `submode_start_time`/`submode_parm0`; `target_objnum`+`target_signature`; `goal_objnum`/`guard_objnum`/`ignore_objnum`; waypoint cursor (`wp_list`/`wp_index`/`wp_dir`/`wp_flags`); path cursor (`path_start`/`path_cur`/`path_length`/`path_dir`, `mp_index`, `path_create_pos/orient`); docking (`dock_index`/`dockee_index`/`dock_path_index`/`dock_objnum`); the per-instance skill-scaled combat floats `ai_accuracy/ai_evasion/ai_courage/ai_patience`; big-ship attack point (`big_attack_point`/`big_attack_surface_normal`); a large bank of `timestamp()` timers (`choose_enemy_timestamp`, `next_predict_pos_time`, `shield_manage_timestamp`, `primary/secondary_select_timestamp`, `scan_for_enemy_timestamp`, `force_warp_time`…); and the embedded goal array `ai_goal goals[MAX_AI_GOALS]` + `active_goal` + `goal_check_time`.
  - AI-class table: `ai_class Ai_classes[MAX_AI_CLASSES]` (MAX 10) with `char *Ai_class_names[]`, `Num_ai_classes`. `struct ai_class` (`ai.h` ~185) = name + `float ai_accuracy/ai_evasion/ai_courage/ai_patience[NUM_SKILL_LEVELS]` (5 skill levels each). Parsed from **ai.tbl** by `parse_aitbl()`/`parse_ai_class()` (~621) under `#AI Classes`. A ship's class is `Ship_info[].ai_class`; at spawn `init_ai_object()`/`init_ai_info` bakes the per-skill row into the flat `aip->ai_accuracy` etc. via `Ai_classes[...].ai_accuracy[Game_skill_level]` (~13605).
  - Goal record: `struct ai_goal` (`ai.h` ~112) = `signature` (unique per mission, from `Ai_goal_signature++`), `ai_mode` (an `AI_GOAL_*` value, distinct namespace from `AIM_*`), `ai_submode`, `type` (`AIG_TYPE_EVENT_SHIP/EVENT_WING/PLAYER_SHIP/PLAYER_WING/DYNAMIC`), `flags` (`AIGF_*`), `time` (issue Missiontime, tiebreak), `priority` (0–100), `ship_name`(+`ship_name_index` into `Goal_ship_names[]`), `wp_index`, and docker/dockee name-or-index unions. Stored as a fixed array `goals[MAX_AI_GOALS]` per `ai_info` (not a linked stack): index 0 is by-convention the active goal because the array is kept sorted; `active_goal` is the index, or the sentinel `AI_ACTIVE_GOAL_DYNAMIC (999)` for runtime combat goals. `AI_GOAL_*` mode constants + `AIG_TYPE_*` + `AIGF_*` live in `aigoals.h`.
- **Mechanism:**

  **(a) Behavior state machine.** 21 modes `AIM_CHASE=0 … AIM_WARP_OUT=20` (`ai.h` ~143). `ai_execute_behavior()` switches on `aip->mode`; each handler further switches on `aip->submode`. Submode families (`ai.h` ~195): chase/attack submodes (`SM_ATTACK`, `SM_SUPER_ATTACK`, `SM_EVADE`, `SM_EVADE_SQUIGGLE`, `SM_EVADE_BRAKE`, `SM_GET_BEHIND`, `SM_GET_AWAY`, `SM_EVADE_WEAPON`, `SM_FLY_AWAY`, `SM_ATTACK_FOREVER`, `SM_STEALTH_FIND/SWEEP`, and big-ship `SM_BIG_APPROACH/CIRCLE/PARALLEL`); docking `AIS_DOCK_0..4A`/`AIS_UNDOCK_0..4`; guard `AIS_GUARD_PATROL/ATTACK/STATIC`; strafe `AIS_STRAFE_ATTACK/AVOID/RETREAT1/RETREAT2/POSITION`; warp `AIS_WARP_1..5`. `ai_chase()` immediately re-routes to `ai_cruiser_chase()` if self is BIG/HUGE, or `ai_big_chase()` (aibig) if the *target* is BIG/HUGE — i.e. small-vs-big combat is handled in aibig even from `AIM_CHASE`. `AIM_WARP_OUT` and `AIM_PLAY_DEAD` are short-circuited directly in `ai_frame` before behavior dispatch.
    - Steering primitives: `ai_turn_towards_vector(dest, objp, frametime, turn_time, slide_vec, rel_pos, bank_override, flags, rvec)` (~1030) is the universal "point the nose" routine — it computes a desired forward vector, applies rotational vel/accel limits (`2*PI/turn_time`), banks (Shivan-only hard bank via `bank_override`), and only turns if the engine subsystem is alive. Skill scaling is applied *here*: `turn_time *= Turn_time_skill_level_scale[Game_skill_level]` for enemy-team ships unless `AITTV_FAST` is set. `accelerate_ship(aip, accel)` sets throttle; `turn_away_from_point()` for evasion. Higher-level wrappers `turn_towards_point`/`turn_towards_tangent`. Position prediction: `set_predicted_enemy_pos()`/`compute_time_to_enemy()` with lead scaled by accuracy.
    - Collision/evasion: `maybe_evade_dumbfire_weapon()` runs after *every* behavior; `ai_endangered_by_weapon()`/`ai_update_danger_weapon()` track incoming fire (`danger_weapon_objnum`); `might_collide_with_ship()` and the big-ship recover path (`maybe_big_ship_collide_recover_frame`, `big_collision_normal`/`big_recover_pos_1/2`); `ai_avoid_shockwave()` (`AIF_AVOID_SHOCKWAVE`). Weapon evasion is its own mode `AIM_EVADE_WEAPON`/`evade_weapon()` but can also run as chase submode `SM_EVADE_WEAPON`.

  **(b) Goal / order system (`aigoals.cpp`).** Each frame `ai_frame` calls `ai_process_mission_orders(objnum, aip)` (~1477): it runs `validate_mission_goals()` (drops satisfied/unachievable goals via `ai_mission_goal_achievable()` at ~976; sets `AIGF_GOAL_ON_HOLD` for not-yet-knowable ones), then `prioritize_goals()` (~1392) which is a plain `qsort(aip->goals, MAX_AI_GOALS, …, ai_goal_priority_compare)`. The comparator (~1349) sorts *descending* by: ON_HOLD last, then `AIGF_GOAL_OVERRIDE` first, then `priority`, then `time` (newer wins ties). Goal[0] is thus the active goal; if its signature is unchanged the function early-outs. Otherwise a `switch (current_goal->ai_mode)` (~1544) *installs* the goal into the behavior machine by calling the ai.h interface functions: `ai_attack_object`, `ai_attack_wing`, `ai_set_guard_object`/`ai_set_guard_wing`, `ai_start_waypoints`, `ai_dock_with_object`, `ai_set_attack_subsystem` (for disable/disarm/destroy-subsys, which also flips target `OF_PROTECTED`), `ai_warp_out`, etc. Player-ship goals are quick-outed unless `AI_GOAL_FORM_ON_WING`.
    - Completion/removal: `ai_mission_goal_complete(aip)` (~377) clears the active goal; `ai_remove_ship_goal`; purge logic — goals in `PURGE_GOALS` (`AI_GOAL_IGNORE|DISABLE_SHIP|DISARM_SHIP`) mark others `AIGF_PURGE` via `ai_goal_purge_invalid_goals`. Docking name→index fixup happens lazily in `ai_goal_fixup_dockpoints()` (~516) using `model_find_dock_index()` (cargo vs rearm dock types).
    - **SEXP coupling (the exact bridge):**
      1. `code/parse/sexp.cpp` defines the mapping table `sexp_ai_goal_link Sexp_ai_goal_links[]` (~274) pairing each `AI_GOAL_*` with its SEXP operator `OP_AI_*` (chase/dock/undock/warp/waypoints/destroy-subsys/disable/disarm/guard/chase-any/evade/stay-near/keep-safe-distance/ignore/stay-still/play-dead). `Num_sexp_ai_goal_links` counts it; `query_sexp_ai_goal_valid()` (~8955) reverse-looks-up via `ai_query_goal_valid()`.
      2. When a mission event fires an `ai-*` operator, sexp.cpp calls `ai_add_ship_goal_sexp(sindex, AIG_TYPE_EVENT_SHIP, &Ai_info[...])` or `ai_add_wing_goal_sexp(sindex, AIG_TYPE_EVENT_WING, num)` (sexp.cpp ~4077/4093/4110). Mission parse installs initial orders the same way: `missionparse.cpp:1238` `ai_add_ship_goal_sexp(..., AIG_TYPE_EVENT_SHIP, aip)` and `:2280` `ai_add_wing_goal_sexp(..., AIG_TYPE_EVENT_WING, wingnum)`.
      3. `ai_add_ship_goal_sexp(sexp, type, aip)` (aigoals.cpp ~832) finds an empty slot (`ai_goal_find_empty_slot`) and calls **`ai_add_goal_sub_sexp(sexp, type, aigp)` (~662)** — this is the actual SEXP→goal decoder: it reads the SEXP node's operator with `find_operator()` and, per `OP_AI_*`, walks `CDR`/`CTEXT` to pull ship name (`ai_get_goal_ship_name`), subsystem/dock-point names, waypoint path, and priority (`atoi`), stamping `aigp->ai_mode`, `signature`, `time=Missiontime`, and `flags`. Player-issued priorities ≥ `PLAYER_PRIORITY_MIN` are clamped down so mission scripting always outranks player orders. Player orders (from the comm menu) enter through the parallel `ai_add_ship_goal_player`/`ai_add_wing_goal_player` path and the direct `ai_*` interface calls (`ai_attack_object`, `ai_dock_with_object`, `ai_ignore_object`…), tagged `AIG_TYPE_PLAYER_*`.

  **(c) Big-ship AI (`aibig.cpp`).** `ai_big_ship(objp)` (~1055) is the `AIM_BIGSHIP` handler (capital ships don't fixate one target). Small-ship-attacking-a-capital is `ai_big_chase()` (~767) via chase re-route. Attack-point selection: `ai_big_pick_attack_point(objp, attacker, attack_point, fov)` (~225) and `ai_big_pick_attack_point_turret()` (~205) pick a surface point on the target hull (using `ai_bpap()` ~87 to project/clip the point to a visible spot within FOV and weapon range), cached in `aip->big_attack_point`/`big_attack_surface_normal`, re-picked on `pick_big_attack_point_timestamp`. Subsystem targeting via `ai_big_maybe_follow_subsys_path()` (~363) drives the ship down a model subsystem path so it can hit a specific subsystem. Weapons: `ai_big_maybe_fire_weapons()` (~665). Strafe runs: `ai_big_maybe_start_strafe()`/`ai_big_maybe_enter_strafe_mode()` (~496/1464) enter `AIM_STRAFE`; `ai_big_strafe()` (~1414) sequences the strafe submodes `ATTACK→AVOID→RETREAT1/2→POSITION` (`ai_big_strafe_attack/avoid/retreat1/retreat2/position`, `ai_big_strafe_maybe_retreat`), and `ai_big_strafe_maybe_attack_turret()` retaliates against the turret that hit it. `ai_big_evade_ship`/`ai_big_avoid_ship` handle physical avoidance of the huge hull.

  **(d) Turret AI (in `aicode.cpp`, "TURRET" section ~9870–10593).** Driven from `process_subobjects(objnum)` (~10656): iterates `shipp->subsys_list`, and for each live `SUBSYSTEM_TURRET` with firing points calls `ai_fire_from_turret(shipp, ss, parent_objnum)` (~10334). Each turret has its own enemy (`ss->turret_enemy_objnum`/`_sig`) independent of the ship's target. Flow: guard clauses (Ai_firing_enabled, disruption `ship_subsys_disrupted`, turret-lock/beam-free flags) → `aifft_rotate_turret()` (~9914) aims the turret submodel toward `predicted_enemy_pos` every frame regardless of fire timer → target selection `find_turret_enemy()` (~2521) / `get_nearest_turret_objnum()` (~2380) gated by `turret_should_pick_new_target()`, `valid_turret_enemy()`, huge-weapon-only-vs-big-ships rule, `OF_PROTECTED`/`OF_BEAM_PROTECTED` filtering, and `is_target_beam_valid()` → subsystem sub-targeting via `aifft_find_turret_subsys()` (~10003, ranks up to `aifft_max_checks` subsystems) → field-of-fire test `object_in_turret_fov()`/dot vs `tp->turret_fov` with per-weapon-class fire cones (`AICODE_TURRET_DUMBFIRE_ANGLE`/`HEATSEEK_ANGLE`, aspect via `turret_should_fire_aspect()`). Firing: `turret_fire_weapon()` (~10206) dispatches by weapon flags — **beam** (`WIF_BEAM` → `beam_fire()` with a `beam_fire_info`, requires `SW_FLAG_BEAM_FREE`), **swarm** (`WIF_SWARM` → `turret_swarm_set_up_info()` then staggered `turret_swarm_fire_from_turret()` ~10289), **flak** (`WIF_FLAK` → `flak_jitter_aim`/`flak_pick_range` for the cone/airburst effect), **spawn** (`WIF_SPAWN` fires on ≥3 nearby enemies rather than FOV), else normal `weapon_create()`+`weapon_set_tracking_info()`. Fire rate via `turret_set_next_fire_timestamp()`/`turret_next_fire_stamp`.

- **Rare knowledge (mining value):**
  - **Skill scaling is spread across two mechanisms.** (1) Per-class ai.tbl floats indexed by `Game_skill_level` and flattened per ship at spawn (accuracy→aim error `(1-ai_accuracy)*4` at ~5841/5915; courage/patience/evasion). (2) Hard-coded `[NUM_SKILL_LEVELS]` global tables in aicode.cpp ~285–316: `Turn_time_skill_level_scale {3.0,2.2,1.6,1.3,1.0}` (enemies turn *slower* on easy), `Max_allowed_player_homers {2,3,4,7,99}`, `Skill_level_max_attackers {2,3,4,5,99}` (caps simultaneous attackers — passed to `find_enemy`), `Skill_level_delay` (reaction lag on position prediction), `Link_energy_levels_*`, `In_range_time`, `Aiming_error`, `Cmeasure_fire_chance`, `Shield_manage_delays`. There is **no AI-profiles system** (that is an fs2open invention) — this is retail's flat, table-driven tuning; behavior is fixed by ai.tbl + these arrays.
  - **Goal priority arbitration** is entirely the qsort comparator + priority clamp: ON_HOLD demotes, `AIGF_GOAL_OVERRIDE` (paired with dynamic goals) promotes above everything, then numeric priority, then recency. Runtime combat decisions bypass the mission goal list via the `AI_ACTIVE_GOAL_DYNAMIC (999)` sentinel — dynamic targeting doesn't allocate a goal slot. Player orders are silently clamped below `PLAYER_PRIORITY_MIN` so designer orders win.
  - **Docking is a hand-rolled multi-stage state machine** over model dock paths, not physics-solved: `ai_dock()` steps `AIS_DOCK_0→1→2→3/3A→4/4A`, each stage calling `dock_orient_and_approach(objp, dobjp, DOA_*)` (~8111) which thrusts along the model's docking path (`dock_index`/`dockee_index`/`dock_path_index`, resolved from `model_find_dock_index()` by dock type — cargo vs rearm). During stages ≥ `AIS_DOCK_2` the ship flies under thruster control (`rfc=0` in `ai_process`), not flight controls. Undock mirrors it `AIS_UNDOCK_0→4`. Rearm/repair support ships reuse this via `ai_rearm_repair`/`AI_GOAL_REARM_REPAIR`, which also forces all other goals ON_HOLD while docked.
  - **Waypoint & path following** are distinct: `AIM_WAYPOINTS` walks `Waypoint_lists[]` (`wp_index`/`wp_dir`, `WPF_REPEAT`/`WPF_BACKTRACK`), while `AIM_PATH`/`ai_path()` follows *model* paths (`Path_points[]` global pool, `create_model_path`/`ai_find_path`) — used for fighter-bay emerge/depart (`AIM_BAY_EMERGE/DEPART`, `ai_acquire_emerge_path`/`ai_acquire_depart_path`) and subsystem approach. Bay emerge/depart suppress goal processing (`ai_process_mission_orders` early-returns) until the path is done.
  - Stealth pursuit is modeled with position-error growth: `AIF_STEALTH_PURSIUT`, `stealth_last_pos`/`stealth_velocity` + `SM_STEALTH_FIND`/`SWEEP` re-acquire a stealth ship by predicted position when not directly visible.
  - Turrets keep firing on BIG/HUGE ships even after the ship is `SF_DYING` — deliberate (comment at ~13473: "its turrets still fire, like I was quoted in a magazine. -- MK").
  - `SM_ATTACK_FOREVER`: a fighter/bomber whose engines are destroyed is forced into permanent attack (never evades) by `process_subobjects` (see Port notes for the retail bug this caused).
- **Deps:** ship (`Ships[]`, `ship_subsys`, subsystem strength/disruption, `Ship_info`/ai.tbl class index), object (`Objects[]`, signatures, `OF_PROTECTED`/`OF_BEAM_PROTECTED`), physics (`physics_read_flying_controls`, `phys_info`, thruster control), weapon (`weapon_create`, `weapon_set_tracking_info`, `Weapon_info` flags WIF_*, `beam_fire`, flak), model (dock paths `model_find_dock_index`, model paths `Path_points`, subsystem geometry `ship_get_global_turret_info`), sexp/mission (`ai_add_*_goal_sexp`, `Sexp_ai_goal_links`, missionparse installs goals), math (`vecmat`: `vm_vec_*`, `vm_vector_2_matrix`, fixed-point `fix`/`Missiontime`).
- **Extraction seams:** Deeply woven — the AI reads and writes ship/object/physics state directly (no interface layer) and the goal system is bidirectionally coupled to sexp.cpp (`Sexp_ai_goal_links` in parse/, decode logic in aigoals.cpp). A clean cut is only possible at three narrow seams: (1) the `ai_process()`/`ai_frame()` per-frame entry from the ship loop; (2) the ai.h "interface from goals code to AI" block (`ai_attack_object`, `ai_dock_with_object`, `ai_set_guard_*`, `ai_start_waypoints`, `ai_warp_out`…) which is the only sanctioned way in; (3) the `ai_add_*_goal_sexp` boundary between sexp.cpp and aigoals.cpp. Turret AI could theoretically split out (self-contained TURRET section, only ship_subsys + weapon deps) but currently shares aicode.cpp globals (`Pl_objp`, skill tables).
