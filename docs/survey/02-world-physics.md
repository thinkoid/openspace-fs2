# Cluster 02 — World & physics

Subsystems: **object**, **physics**, **debris**, **asteroid**, **fireball**,
**jumpnode**, **observer**. The entity pool, the rigid-body integrator, and the
minor world objects that ride on them. See [README](README.md) for conventions.

---

### object  (~5.7k master)
- **Purpose:** The central entity system: a fixed pool of generic `object`s (ships, weapons, debris, asteroids, fireballs, etc.) plus the per-frame move/render loop and the broad-phase collision-pair engine.
- **Entry points:** `object/object.cpp: obj_create()`, `obj_delete()`, `obj_move_all()` (master per-frame driver), `obj_move_call_physics()`, `obj_render()`; `object/objcollide.cpp: obj_add_pair()`, `obj_check_all_collisions()`, `objects_will_collide()`; per-type handlers `object/collideshipship.cpp: collide_ship_ship()`, `object/collideshipweapon.cpp`, `object/collideweaponweapon.cpp`, `object/collidedebrisship.cpp`.
- **Core state:** `object Objects[MAX_OBJECTS]` (1000, 300 in demo) + the `object` struct (`object.h`), intrusively linked into `obj_free_list` / `obj_used_list` / `obj_create_list`; `Highest_object_index`, `num_objects`, `Player_obj`, `Viewer_obj`; collision pairs live in `objcollide.cpp: Obj_pairs[MAX_PAIRS]` (8000) with `pair_used_list`/`pair_free_list` and the `obj_pair` struct (`objcollide.h`) carrying a `check_collision` function pointer.
- **Mechanism:** Objects are a slot pool threaded onto free/used intrusive doubly-linked lists; `obj_create` pulls from free list, sets `type`/`instance` (index into the type-specific array like `Ships[]`), and appends to a create list merged at frame start. `obj_move_all` walks the used list calling pre-move, saving `last_pos`/`last_orient`, `obj_move_call_physics`, post-move, then `obj_check_all_collisions`. Collisions are broad-phased into `obj_pair`s (created in `obj_add_pair`, dispatched by type to the collide*.cpp handlers); each pair carries a `next_check_time` timestamp so far-apart pairs are re-checked lazily, and a pair is deleted once it reports a definite collision.
- **Rare knowledge:** Worth mining: the lazy collision-pair scheduler (`obj_add_pair`/`obj_check_all_collisions` with per-pair `next_check_time` and one-shot pair removal), the recursive swept-sphere line-intersection test `objcollide.cpp: collide_subdivide()` and `objects_will_collide()`, `weapon_will_never_hit()` pruning, and the full impulse-with-restitution collision resolution in `collideshipship.cpp: ship_ship_check_collision()` (`COLLISION_ROTATION_FACTOR` "hack decrease rotation", moment-of-inertia `get_I_inv`, `coeff_restitution`, Player_obj treated as infinite-rotational-inertia special case). `UNUSED_OBJNUM = -MAX_OBJECTS*2` sentinel convention.
- **Deps:** physics (per-object `phys_info`, integration, whack), model (`mc_info` polygon collision), ship/weapon/debris/asteroid/fireball (type dispatch and `*_check_collision`/`*_hit`), math/vecmat, timer, beam.
- **Extraction seams:** Core `obj_create/delete/move` + list machinery is fairly self-contained on physics+math; the collide*.cpp handlers are deeply entangled with ship/weapon/shield/damage internals and would need to come along or be stubbed. Cut line: keep the `Objects[]` pool + pair scheduler; treat the per-type collision handlers as pluggable callbacks (they already dispatch through `obj_pair.check_collision`).
- **Port notes:** `obj_move_all` has a commented-out post-move velocity-recompute block (DA, "Commented out 2/23"); `#if 0 ... DONT_REMOVE_PAIRS` debug branch retained in `obj_check_all_collisions`; observer objects short-circuited in the main move loop.

### physics  (~1.2k master)
- **Purpose:** Frame-rate-independent 6-DOF rigid-body integrator for every physics object: exponential velocity/rotvel ramping plus impulse (whack) and shockwave response.
- **Entry points:** `physics/physics.cpp: physics_sim()` (per-frame driver) → `physics_sim_vel()` + `physics_sim_rot()`; `apply_physics()` (the scalar integrator kernel); `physics_read_flying_controls()` (turns control input into desired vel/rotvel); `physics_apply_whack()`, `physics_apply_shock()`, `physics_collide_whack()`; `physics_predict_pos()`/`physics_predict_vel()`.
- **Core state:** the `physics_info` struct (`physics.h`) — `mass`, `I_body_inv` (inverse moment-of-inertia matrix), `vel`/`desired_vel`, `rotvel`/`desired_rotvel`, `max_vel`/`max_rotvel`, `side_slip_time_const`, `rotdamp`, `prev_ramp_vel`, and a `flags` bitfield (`PF_REDUCED_DAMP`, `PF_IN_SHOCKWAVE`, `PF_DEAD_DAMP`, `PF_SPECIAL_WARP_IN/OUT`, `PF_CONST_VEL`, `PF_USE_VEL`); file-scope `Physics_viewer_bank`, `Viewer_physics_info`.
- **Mechanism:** `apply_physics` is the whole integrator: given a damping time-constant it computes `new_vel = dv*exp(-t/damping)+desired_vel` and the exact position delta over the frame, so results are independent of frame time. `physics_sim_vel` rotates world velocity into body coords, ramps each axis separately (forward axis usually undamped for the player), and unrotates; `physics_sim_rot` ramps rotational velocity then builds an angle→matrix delta and re-orthogonalizes the orientation. Impulses (`physics_apply_whack`) add `impulse/mass` to velocity and `I_body_inv·(pos×impulse)` to rotvel, temporarily raising damping via `PF_REDUCED_DAMP`.
- **Rare knowledge:** Prime mining target. The closed-form exponential-approach integrator (`apply_physics`) is the era's answer to fixed-timestep instability. Also: `PF_REDUCED_DAMP` decay used to push colliding ships apart (`update_reduced_damp_timestamp`, damp scaled by fraction not fraction² "gives better collision separation"), `SPECIAL_WARP_T_CONST` exponential warp-in/out speed bleed, `physics_apply_shock` computing shockwave torque from projected bounding-box face areas, `ROTVEL_CAP`/`DEAD_ROTVEL_CAP` clamps, and rotational-shake amplitude driven off `myrand()`.
- **Deps:** math/vecmat (matrices, moment of inertia), timer (timestamps), player/control_info for `physics_read_flying_controls`; otherwise nearly standalone.
- **Extraction seams:** Very clean — operates purely on a passed `physics_info` + `matrix`/`vector`, no ownership of objects. `physics_read_flying_controls` is the only piece that reaches into game/player structs; everything else lifts out with just vecmat + a timestamp shim.
- **Port notes:** THIS PROJECT'S FIX — commit `physics: apply_whack divides by the mass it was given, not pi->mass`: `physics_apply_whack()` now does `vm_vec_scale_add2(&pi->vel, impulse, 1.0f/mass)` using the passed `mass` parameter, where `[retail]` `code/physics/physics.cpp` used `1.0f/pi->mass` (retail lines ~1085 and ~1300). Callers in ship/shiphit.cpp already passed combined docked mass, so retail effectively ignored it. Also carries commented-out afterburner-shake block and disabled `PHYS_DEBUG` excess-velocity Asserts.

### debris  (~1.1k master)
- **Purpose:** Flying ship/hull debris chunks — spawn on ship breakup, tumble under physics, spark with electric arcs, collide and deal damage, then expire.
- **Entry points:** `debris/debris.cpp: debris_create()`, `debris_process_pre()`/`debris_process_post()` (per-frame), `debris_render()`, `debris_hit()`, `debris_check_collision()`, `debris_start_death_roll()`, `calc_debris_physics_properties()`, `debris_find_oldest()`.
- **Core state:** `debris Debris[MAX_DEBRIS_PIECES]` (64, 48 in demo) + the `debris` struct (`debris.h`) with `arc_pts[MAX_DEBRIS_ARCS][2]` / `arc_timestamp[]` electric-arc data, `flags` (`DEBRIS_USED`, `DEBRIS_EXPIRE`), lifetime/next-fireball timestamps; `Num_debris_pieces`, `Debris_model`/`Debris_vaporize_model`, `Debris_textures[]`.
- **Mechanism:** `debris_create` allocates an `object` of `OBJ_DEBRIS`, picks a hull submodel or generic chunk, and seeds tumbling rotvel plus outward velocity from the explosion center; `calc_debris_physics_properties` derives `I_body_inv` from the bounding box. Per frame it ages the piece, spawns fireballs and lightning arcs, and when full it recycles the oldest via `debris_find_oldest`. Collisions use `debris_check_collision` (polygon `mc_info` sphere/model test) feeding `debris_hit`.
- **Rare knowledge:** Worth mining: the electric-arc effect bookkeeping (`arc_pts`/`arc_timestamp` with `MAX_DEBRIS_ARCS`), the oldest-piece recycling under the small `MAX_DEBRIS_PIECES` cap, "hull" vs generic-chunk distinction and `Debris_vaporize_model`, and the inertia-tensor-from-bounding-box approximation in `calc_debris_physics_properties`.
- **Deps:** object (pool/collision pairs), physics (tumble/whack, `I_body_inv`), model (submodels, collision), fireball (explosion/spark visuals), particle, ship (source ship, damage).
- **Extraction seams:** Moderately entangled — depends on ship internals for creation and on model submodel data; the debris pool + physics-property calc are liftable, but spawn and hit paths are woven into ship destruction.
- **Port notes:** — (no distinctive port markers observed in excerpts).

### asteroid  (~2.1k master)
- **Purpose:** Procedural asteroid field: spawns and wraps a torus of tumbling rocks around the player, splits them on death, warns escorts of impacts, and applies area-effect blast damage.
- **Entry points:** `asteroid/asteroid.cpp: asteroid_create()`, `asteroid_create_all()`, `asteroid_sub_create()` (split children), `asteroid_process_pre()`/`asteroid_process_post()`, `asteroid_hit()`, `asteroid_check_collision()`, `asteroid_maybe_break_up()`, `asteroid_wrap_pos()`/`asteroid_should_wrap()`, `asteroid_aim_at_target()`, `asteroid_parse_tbl()`.
- **Core state:** `asteroid Asteroids[MAX_ASTEROIDS]` + `asteroid` struct (`asteroid.h`; `check_for_wrap`/`check_for_collide` timestamps, `collide_objnum`/`collide_objsig`, `target_objnum`, `final_death_time`); `asteroid_field Asteroid_field` (min/max bounds, optional inner bound, average `vel`/`speed`, `field_type` active/passive, `debris_genre`); `asteroid_info Asteroid_info[]` (parsed table); a private object list `Asteroid_obj_list` (`asteroid_obj_list_add/remove`).
- **Mechanism:** `asteroid_create_all` scatters `num_initial_asteroids` between the field's outer and optional inner bound, each with randomized tumble and the field's average velocity plus jitter. Each frame `asteroid_should_wrap`/`asteroid_wrap_pos` teleports rocks that leave the box to the opposite face (a toroidal field), keeping density constant; `inner_bound_pos_fixup` pushes them out of a protected inner box. `asteroid_process_post` throttles collision checks against escorted ships via timestamps, and death splits a rock into smaller children via `asteroid_sub_create`.
- **Rare knowledge:** Rich mining target: the wrap-around "infinite field" trick (`asteroid_wrap_pos` with inner/outer bounds), the escort-collision early-warning system (`asteroid_collide_objnum`, `asteroid_time_to_impact`, `asteroid_aim_at_target` — asteroids that home on targets), speed capping (`asteroid_cap_speed`), the maintained side `Asteroid_obj_list`, and area-effect blast application (`asteroid_do_area_effect` with inner/outer radius falloff).
- **Deps:** object, physics (tumble/velocity), model, fireball (explosions), debris genre sharing (`MAX_DEBRIS_TYPES`), ship/ai (targeting, escort warnings), parse (table loading), hud (impact warnings).
- **Extraction seams:** Field-generation + wrap logic is self-contained on object+physics+rng; the collision-warning and area-damage paths reach into ship/ai and would need cutting or stubbing. Natural cut: keep field spawn/wrap/split, sever `asteroid_aim_at_target`/escort-warn.
- **Port notes:** — (none evident in excerpts).

### fireball  (~1.0k master)
- **Purpose:** Explosion animations AND warp-hole effects as lightweight objects — animated LOD-selected bitmaps/models with lifetimes, plus the 3D warp portal render.
- **Entry points:** `fireball/fireballs.cpp: fireball_create()`, `fireball_process_post()`, `fireball_render()`, `fireball_set_framenum()`, `fireball_get_lod()`, `fireball_is_warp()`, `fireball_free_one()`/`fireball_is_perishable()`, `fireball_parse_tbl()`; `fireball/warpineffect.cpp: warpin_render()`.
- **Core state:** `fireball` runtime array + `fireball_info`/`fireball_lod` tables (`fireballs.h`, `MAX_FIREBALL_TYPES`=6), warp-open/close sound bookkeeping; `warpineffect.cpp` face/vertex geometry for the portal.
- **Mechanism:** `fireball_create` allocates an `OBJ_FIREBALL` object with a lifetime and a chosen LOD animation; `fireball_process_post` advances the animation frame from elapsed life (`fireball_lifeleft_percent` → `fireball_set_framenum`) and kills the object when the animation completes. `fireball_get_lod` selects detail by on-screen size/distance. Warp fireballs additionally drive open/close sounds and render a rotating textured portal disc via `warpin_render`.
- **Rare knowledge:** Worth mining: distance/size-driven LOD selection for explosions (`fireball_get_lod`), the perishability/recycling scheme (`fireball_is_perishable`, `fireball_free_one`) that lets non-critical explosions be culled under object pressure, and the procedurally-built warp-portal geometry in `warpineffect.cpp` (`draw_face`, `norm` DCF console cmd).
- **Deps:** object (pool), bmpman/anim (animations), model+render (warp geometry), gamesnd (warp sounds), parse (table).
- **Extraction seams:** Fairly self-contained view/effect subsystem on top of object + bmpman; warp-sound hooks into gamesnd are the only real tie. Liftable with a rendering shim.
- **Port notes:** commented-out `//JAS` fireball-type check in object.cpp's physics move path; otherwise clean.

### jumpnode  (~0.1k master)
- **Purpose:** Subspace jump-node markers — a tiny render-only object type, largely a FRED/editor and visual entity.
- **Entry points:** `jumpnode/jumpnode.cpp: jumpnode_create()`, `jumpnode_render()`, `jumpnode_render_all()`.
- **Core state:** `jump_node_struct Jump_nodes[MAX_JUMP_NODES]` (3) with `modelnum`/`objnum`/`name`; `Num_jump_nodes` (`jumpnode.h`).
- **Mechanism:** `jumpnode_create` makes an `OBJ_JUMP_NODE` object at a position with a loaded model; rendering draws the node model (view-position aware). Nodes don't move or collide — physics is skipped for the type in `obj_move_call_physics`.
- **Rare knowledge:** — (mundane marker object).
- **Deps:** object, model, parse (`parselo.h`).
- **Extraction seams:** Trivially self-contained; depends only on object + model.
- **Port notes:** —

### observer  (~0.1k master)
- **Purpose:** Free-flying camera/spectator object (multiplayer observer, reused for some single-player camera cases) with its own capped velocities.
- **Entry points:** `observer/observer.cpp: observer_create()`, `observer_delete()`, `observer_get_eye()`, `observer_init()`.
- **Core state:** `observer Observers[MAX_OBSERVER_OBS]` (17) + `observer` struct (`objnum`, `target_objnum` unused, `flags` with `OBS_FLAG_USED`); velocity caps `OBS_MAX_VEL_X/Y/Z` (85) in `observer.h`; `Num_observer_obs`.
- **Mechanism:** `observer_create` allocates an `OBJ_OBSERVER` object and sets up a `physics_info` bounded by the `OBS_MAX_VEL` constants so the spectator flies with normal flying-controls physics but no collision/render. `observer_get_eye` returns the eye position/orientation for the camera. The main `obj_move_all` loop explicitly skips observer objects (their physics is handled via the control path).
- **Rare knowledge:** Minor: observer objects are special-cased out of the standard object move loop and carry an unused `target_objnum` (design vestige noting possible future single-player use).
- **Deps:** object, physics (flying-controls integration), vecmat.
- **Extraction seams:** Self-contained; thin wrapper over object + physics.
- **Port notes:** — (`target_objnum` "not used as of yet" comment is original, not a port artifact).
